# SIMD optimisation

The scalar GTE and Needle kernels remain the correctness oracle and universal fallback. Runtime default is automatic staggered dispatch: AVX2 on capable amd64, SSE2 on baseline amd64 (including DiskStation J3455), NEON on ARM64, then scalar. `go/internal/simd` provides the shared substrate selected with `MEMENTO_SIMD`:

* `scalar` -- universal exact-order fallback and explicit override;
* `sse2` -- baseline amd64 path suitable for older Intel systems such as the Celeron J3455;
* `avx2` -- runtime-gated AVX2 tier (requires AVX2 and FMA capability);
* `neon` -- ARM64 ASIMD/NEON path;
* `auto` -- AVX2, then SSE2, then NEON, then scalar; this is the default when `MEMENTO_SIMD` is unset.

The DiskStation Celeron J3455 path is an explicit release gate: `GOAMD64=v1` builds run `memento-simd-check` with AVX/AVX2/FMA disabled and must report `backend=sse2`; release CI runs the same helper under QEMU's Westmere CPU model before the existing scalar model smoke. Backend selection is validated once through an `Engine`; hot calls do not repeat CPU-policy checks. Dot products permit a bounded reduction-order difference (`1e-4` relative in synthetic tests). AXPY currently matches scalar float32 bits. Model constructors now select `auto` by default. `MEMENTO_SIMD=scalar` forces the exact-order oracle; explicit unavailable tiers fail closed. Changed reduction order can still affect embeddings or generated tokens, so real-model/corpus gates remain mandatory.

On the local Intel i7-12700, a 384-element persistent-dispatch dot benchmark measured scalar at roughly 63–71 ns/op, SSE2 at roughly 52–58 ns/op, and AVX2 at roughly 26–28 ns/op. SSE2 was about 1.2–1.35× faster and AVX2 about 2.3–2.7× faster. A 32×384 by 384×384 GTE projection measured roughly 3.45–3.80 ms scalar versus 0.28–0.29 ms AVX2, around 12–13× faster. Needle's full-vocabulary 8,192×384 argmax remained about 1.4–1.8 ms for both scalar and AVX2, indicating memory-bandwidth/dispatch overhead dominates that kernel. These are microbenchmarks, not end-to-end inference results.

ARM64 assembly cross-compiles in the normal static release gate. The NEON evidence gate was closed with real-hardware differential and performance measurements on `orangepi6plus.local`. GTE linear projections and Needle attention/argmax accept the optional Engine. Loaded service models read `MEMENTO_SIMD`; unset selects `auto`, while invalid or unavailable explicit tiers fail startup. Synthetic GTE projection and Needle attention/argmax tests compare against scalar with explicit tolerances.

The recovered real model assets now pass the gated integration suite on x86-64: GTE 5/5, Needle generation 5/5, 31 tensor hashes, 8,192 vocabulary pieces/token decodes, and the held-out Rust corpus at 360/360 exact outputs/errors. Forced scalar, SSE2 and automatic dispatch produce the same five Needle outputs and all pass the GTE `1e-5` maximum-absolute-error gate. In the gated set, GTE took approximately 0.87 s scalar, 0.33 s SSE2 and 0.27 s auto; Needle remained roughly 18 s for all three, confirming that its tested path is not compute-bound by these kernels. Reproducible commands and measurements are recorded in [`../evidence/go-real-model-simd-2026-09-19.json`](../evidence/go-real-model-simd-2026-09-19.json). Real ARM64 evidence is now complete on `orangepi6plus.local` (CIX P1 CD8160, four Cortex-A520 plus eight Cortex-A720 cores, Mali-G720-Immortalis present but unused for these CPU measurements). Automatic dispatch selects NEON. A real-hardware defect in the original manual lane reduction was exposed by model tests, repaired with two native `FADDP` reductions, and locked down with deterministic pseudo-random/tail/aliasing kernel tests. The fixed backend passes GTE 5/5 and exact Needle generation 5/5 under scalar, NEON and auto; the held-out Needle corpus passes 360/360 exact under NEON in 2001.84 seconds. A 384-element dot benchmark measured scalar at 153.8–165.2 ns/op and automatic NEON at 85.47–88.83 ns/op (roughly 1.8× faster). GTE improved from 1.207 s scalar to 0.561 s NEON; Needle remained approximately flat/slightly slower (26.125 s scalar versus 27.292 s NEON), confirming that its end-to-end path is dominated elsewhere. Warm real GTE embedding is held to 2 allocations per operation. Fused row-dot and row-AXPY kernels remove per-output SIMD dispatch, while the amd64 AVX2 row-AXPY path keeps 32 output values in registers across coefficient rows. Needle caches immutable constraint templates, reuses request-local encoder/decoder scratch and rune buffers, and uses a typed SentencePiece BPE heap instead of boxing queue entries through `container/heap`. The current gate is 350 allocations and 1.8 MB per real generation; ordinary local runs reached 307 allocations/op and about 1.77 MB, with allocation profiling lower still. The exact 360-case corpus completed in 387.4 seconds on the same Intel host, versus 1,408.8 seconds for the retained original scalar run. These are regression measurements rather than latency promises.

The NAS replacement is CPU-only by explicit decision. The retained Bookworm Mesa 22.3.6 evidence proves hardware compatibility, but same-process warm GPU measurements remained slower than CPU. Do not package, enable or retest NAS Vulkan without a new decision. See [`../evidence/vulkan-nas-bookworm-2026-09-19.md`](../evidence/vulkan-nas-bookworm-2026-09-19.md).
