# Pure Go port: correctness before optimisation

Branch `go` is an end-to-end replacement project: the service, uMCP, storage/recovery, GTE, Needle and operations tooling, not just the native embedding worker. The original Python/Rust implementation is retained as the test reference until each replacement passes its compatibility gates.

The Go runtime must build with `CGO_ENABLED=0`, without Python, Rust, C inference, native SQLite extensions or external Git commands for core operation. Existing browser JavaScript and static assets can be served unchanged by Go; rewriting the browser in another language is not part of this port. Python/Rust/Git remain permissible in the independent test oracle. SIMD, assembly, quantisation, GPU integration and performance-driven algorithm changes are deferred.

## What runs today

The Go scaffold implements response-envelope constructors, scalar vector encoding/dot/cosine/AXPY, uMCP ID/response/version helpers, HTTP media/header/response rules, and a request dispatcher with isolated contexts, cooperative cancellation and progress. Sync and async Python reference fixtures verify dispatch and progress behaviour, including arbitrary-size JSON integer IDs and exact large-integer progress comparisons. The dispatcher invokes only registered handlers; it is not a complete tool/resource/prompt server. List pagination also matches principal/list-bound cursor bytes and error behaviour from both uMCP bases. A sequential stdio loop now matches both Python bases on blank/final lines, invalid UTF-8 replacement, notifications and requests longer than 64 KiB. It takes implemented handlers and is not yet wired as a Memento daemon. Origin/URL helpers also match fixture-tested Python splitting, host/port and NFKC delimiter checks using the pure-Go `golang.org/x/text` dependency. Dynamic tool registration, sorted discovery, calls/coercion, schema-subset validation and Python-style result text now match sync/async fixtures. Go callers provide explicit parameter/schema metadata; generic Python reflection/API compatibility is not claimed. Resource/template and prompt discovery/execution, content normalisation and subscription registries now match sync/async fixtures. Completion, logging/redaction and server initialise/config composition also match pinned scenarios. The Streamable HTTP handler now matches 41 requests captured from actual sync/async Python servers and includes principal/version-bound UUID sessions, GET event streams, TTL/caps, subscriptions and deletion. Auxiliary routes deliberately own their authentication, as in Python. File mode and TCP now match both reference implementations, with separate sync/async policies for UTF-8, timeouts and line limits. Legacy SSE supports authenticated endpoint handshakes, session-bound messages, notifications and disconnect cleanup, with separate sync queuing and async write acknowledgement. The async raw HTTP parsers and listener now preserve request/header/body limits, pipelining, connection lifetimes and separate sync/async authentication order. Notification delivery now preserves the legacy stdout fallback and active Streamable HTTP suppression, including targeted delivery. The synchronous parser/listener also preserves the pinned Python 3.13.14 header parser, route-dependent body reads, HTTP/0.9 handling, interim responses and HTML errors. uMCP transport argument parsing and dispatch now connect file/stdio/TCP/HTTP/SSE modes, with reference defaults and listening announcements. Memento method wiring and its operational CLI remain unported. Its synthetic fixtures were emitted by the actual pinned Python and Rust implementations, not handwritten copies of expected values. Catalog/help/workflow generation now implements the twenty surface/model configurations, with static/template resources, completion values and the asset-publication prompt. Configured registration fails before mutation unless every operation callback exists, because Python hides tools from discovery without removing them from dispatch. These contracts do not implement the remaining service operations or execute engine.

`go/repository` now ports canonical path validation, reserved-file classification, concept metadata validation and JSON/YAML frontmatter. Differential tests preserve UTC conversion, source coercion quirks, body normalisation and deterministic YAML output for the tested cases. Filesystem checks do not authorise access or make later opens race-safe; broader YAML compatibility, transactions and service operations still need implementation. Structural links and parser-confirmed rename edits now feed bundle scanning, audits and generated indexes/logs. Their differential fixtures cover the current slice; complete CommonMark/URI equivalence and case-fold-equal index ordering are not verified.

The Git store can read existing packed SHA-1 objects/refs and compare tree paths without a Git subprocess. Main publication uses an exclusive Git-compatible lock file, a locked revision recheck and atomic rename, with failures after publication distinguished from failures before it. Exact-revision checkout materialisation writes through Go's rooted filesystem API and preserves executable/link entries. Detached linked worktrees now share the bare object store while keeping their own HEAD/index, and literal exact-path commits reproduce the reference object hashes without moving main. Bootstrap supports seeded and empty repositories and refuses to overwrite existing main. The control store now uses pure-Go SQLite for schema migration and idempotent operation records, including the legacy v5 asset lift. Transaction apply/replay and startup recovery now connect Git commits to operation records, with checkpoint and process-kill tests on either side of publication. Namespace authorisation and the managed access store now preserve protected/trash scope rules, encrypted verifier keys, credential lifecycle and audits against synthetic reference cases. Low-level proposal and attached-asset records now support atomic creation, list queries and stored status updates. ZIP validation, staged asset/ticket records and bounded file reads now preserve raw archive identity, ownership, expiry, one-time consumption and complete-file digest checks for the tested formats. Accepted asset storage preserves metadata bytes and version ordering, using rooted writes that reject symlink targets. Proposal queue refresh classifies conflicting paths and expires old records, retaining review fields and recording status changes in the same SQLite transaction. Proposal visibility checks author/curator ownership and every changed path, including rename destinations; review access also requires writes. The internal rebase operation retains proposal/asset identity and records cleared review fields in history, with the status update and replay result committed together. It shares the repository mutation lock with apply/recovery. Bounded proposal summaries include per-change conflicts and asset/body matches without generating a preview, so missing content does not prevent a review summary. Archival inspection checks index freshness, readable inbound references and retained assets using an existing read-only derived index. Internal review now supports approval, rejection and requested changes with atomic history, summaries and durable replay; approval checks archival freshness where required. Disposable-worktree create/patch/rename/trash helpers now preserve concept bytes, link rewrites and source partial-failure ordering, with rooted writes and exclusive new-file creation. The aggregate mutation callback also applies stored assets and adapts existing asset-backed creates into patches, preserving source digest-check ordering. Full proposal payloads retain bounded history and render Python-compatible previews, including unified diffs. Internal proposal apply now joins authorisation, approved/base checks, worktree mutations and Git publication, followed by proposal status and queue refresh. It preserves the source's post-publication failure states rather than claiming an atomic Git/SQLite commit. Non-model submission now prepares inline/staged assets, checks body and ownership bindings, and commits proposals with one-time staged consumption. Preparation retains the source's separately committed expiry and stale-proposal refresh effects. Internal proposal reads provide detailed/summary views with missing-target preview fallback and separately authorised stored-asset reads. File reads verify archive and content hashes before returning slices. Revision can copy a clean subset into a new curator-owned proposal, keeping paired body/asset changes together and retaining the original record. Proposal lists preserve raw-candidate pagination and bind encrypted cursors to the caller's policy, status and repository revision. The models-disabled derived content index now maintains schema v2, FTS5 rows, structural links and graph metrics on rebuild and path updates, including source partial-commit behaviour. Proposal publication and archival tests use this Go-maintained index. Eventual lexical search now uses the same FTS5 query weights, snippets and namespace filters as Python, with plain-query stop-word handling and offset pagination. Graph traversal applies policy at each hop and reports scoped broken links/orphan flags; status counts visible concepts, and strict reads wait for matching revisions. The index lifecycle now caches initialisation by file identity, distinguishes contention from corruption and retains quarantined databases for inspection before rebuilding. The trusted identity adapter now connects static/managed bearer authentication to live namespace policy and uMCP sessions; managed revocation is enforced on the next HTTP request. Service envelopes now map known failures and preserve revision defaults; unexpected failures reach uMCP's redacted error handler. A test-only HTTP adapter verifies authenticated submission and structured results. The MCP worker admission helper preserves shielded background jobs, the reconciliation slot and drain behaviour, so a request timeout does not cancel an admitted write. Operation reconciliation now probes active writers without blocking and reports scoped committed/in-progress/failed outcomes for the original key. An explicit nine-tool proposal/control subset now registers source-derived schemas, uses one database handle per job and exercises the full authenticated HTTP proposal workflow. Managed grants are rechecked after acquiring the writer lock, and list cursor keys remain shared across jobs. Four registered models-off read tools now expose read/list/search/graph with source access and payload behaviour; the combined development subset now has 28 tools, including real models-off help/status and their resources, projected namespace inventory, manifest comparison, detailed asset metadata, ticket creation/status, accepted-asset retrieval/pruning and direct curator create/patch/rename/trash/restore/purge. The auxiliary staging route accepts bearer-owned uploads or one-time ticket uploads, with replay and expiry checks. Ticket tools check resolved principal roles directly and bypass worker admission and the repository lock, matching Python. The registered HTTP flow issues a ticket, uploads the ZIP, consumes it into a proposal, reviews/applies the proposal and retrieves the identical accepted bytes. Accepted-asset reads authorise the concept, resolve versions and hold the repository lock through range verification and revision capture. Pruning uses the same lock and transaction manager, retaining versions referenced by submitted or approved proposals. A retry with nothing left to prune returns the source's no-op success without a new operation. Direct concept mutations retain review-bypass warnings, prevent body-only edits to asset-backed concepts and recheck those rules before replay. Queue refresh and returned previews run after publication, preserving the source's partial-failure behaviour. Trash/restore move concept bytes without rewriting inbound links or moving ID-addressed assets; confirmed purge removes current concept/asset files while retaining their Git history. Inventory prunes namespace traversal before pagination and parses only selected concepts, returning requested metadata, body hashes and asset-version summaries. Manifest comparison validates explicit or template-mapped targets, rechecks live inventory permissions, and groups up to 50 combined local/remote records by body hash while reporting byte-count and timestamp differences separately. Asset metadata reports bounded version/file lists and skill-body parity without reading archive bytes. Missing creation dates use a pure-Go Git addition-timestamp lookup, verified against linear native-Git history. Models-off status reports scoped concept/proposal counts, stale-index fallback and disabled model readiness; help uses the source catalog contract. Both bypass worker admission, while status shares the repository lock. Admin endpoint wiring, complete configured-surface handlers, enabled semantic search and wider cross-process recovery, optional hot-memory tracking, power-loss durability, reflogs and broader Git configuration/filter/pathspec semantics are unfinished.

`go/gte` now restores the original Go GTE1 layout, tokenizer and scalar transformer algorithms, retaining Memento's Unicode character-boundary fix and cancellation checkpoints. Synthetic Rust oracle cases pass, and a digest-pinned 384-dimensional model test compares five real inputs. The loader currently copies weights; mmap/resource parity, expanded corpora and worker integration remain unfinished. No assembly, native BLAS or fast-math path is enabled.

The Needle NDL1 parser also loads the real model: all 31 tensors, all 8192 vocabulary entries, metadata and BF16-to-float32 hashes match Rust. Pure-Go SentencePiece encoding/decoding (BPE/Unigram, normalisation and byte fallback) and Needle's special-token rules pass synthetic and real tokenizer comparisons. Scalar Needle encoder/decoder, RoPE, grouped attention, KV caches, gated norms and constrained generation are now implemented. Five real generation cases match output/checkpoint sequences, and all 360 held-out queries match complete Rust output strings locally. Native amd64 and ARM64 full-corpus CI both passed in run 35291886039; parser error-text fidelity, broader malformed/configuration cases and service integration remain open. The derived SentencePiece package retains its Apache-2.0 licence separately from Memento's MIT code.

`memento-go version` reports that the service port is incomplete. Its server commands exit explicitly; there is no fake MCP status server. `build/go/memento-embed-go MODEL.gtemodel` is a working scalar framed embedding executable; the unchanged Python subprocess client accepts its output. It caps requests at 4 MiB (a deliberate safe difference from the old unbounded Rust reader), rejects nonfinite outputs rather than panicking, and does not yet match every malformed JSON diagnostic or duplicate-field behaviour.

```sh
make -C go check  # format, vet, zero-uncovered-statement gate, CGO-free build
make -C go race   # test-only cgo for Go's race detector
make -C go fuzz   # bounded initial fuzz runs
make -C go cross  # baseline amd64 and arm64 builds
```

Passing these initial tests does not establish complete uMCP, MCP, storage or inference parity. Every remaining row in the matrix must be implemented and verified before this branch can replace production. No release, migration or deployment is authorised by creating the branch.
